# Steward relationship: separate evidence, retained identities

Current local publication-candidate case, 13 October 2026. `python -B run.py demo --case identity-confirmed` opens the 0.4 case. The original `--case identity` fixture stays 0.3 and is a historical metadata-only/conditional control, not the current one-pair evidence state.

The reader can distinguish a hash-checked authored steward extract from local file-byte verification, see both native IDs and the reported original filename, inspect the exact source/pointer and limitations, then compare unchanged original and one-action-withheld values. No native representative is selected and no denominator is recomputed. Steward confirmation does not adopt the order-robust candidate, qualify every alias or prove independence. The field is a typed relationship, not a global deduplication key.

The app does not authenticate email, acquire images, compare NEFs or establish a public JPEG's processing. The maintainer qualified the received source; the consumer only checks a bundled authored factual summary and exact group binding. An unbundled parent fingerprint is a provenance locator, not a replay of that parent. No raw email, personal addresses or transport headers are bundled. A second permission request is not a prerequisite for this limited factual paraphrase. No source-granted redistribution permission or broader endorsement is claimed.

Only 0.4 may declare `steward_links`. Each link resolves a pinned local statement, a JSON pointer and one existing metadata group. A steward-only statement names exactly both group alternatives, an archive-correspondence evidence class, a date/owner, a reported filename and an HTTPS source pointer. Byte verification, supplied checksums, other-pair confirmation, denominator changes and publication permission must remain literal false. Wrong/extra/subset/adjacent IDs, unsupported evidence types, selected representatives, reference-only sources and malformed fields stop evaluation. Missing or altered sources block the link and hide confirmation values/headlines. HTML/Markdown/JSON must tell the same scoped story.

Original scientific values and the historical flash/identity cases are retained. Public credit and dependent byte identities are explicit projections, not original private receipt bytes. The native schema is accompanied by stricter deterministic consumer checks. The public case is reproduced with `python -B run.py demo --case identity-confirmed`, using only Python's standard library and bundled files. The original mail-intake preparer is not exported; this app cannot reconstruct its unbundled parent correspondence.

Mechanical checks are not uncoached comprehension, full accessibility, owner taste or scientific endorsement. Human acceptance and publication remain separate. Use the historical identity case for the earlier metadata-only comparison; it does not override the current scoped steward confirmation.
