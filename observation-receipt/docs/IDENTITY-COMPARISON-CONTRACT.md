# Identity and conditional-comparison extension

Private version 0.3 candidate, 12 October 2026

## Outcome and first use

A researcher or technical reviewer runs `python run.py demo --case identity`, opens the local viewer and can distinguish unresolved metadata alternatives, the frozen original cohort, and a conditional one-action withholding comparison. The source of every displayed comparison number is inspectable. The existing flash demo and version 0.2 cases continue to work unchanged.

Entry is the shipped README and source-checkout launcher, on a local computer with Python 3.11 or newer. No account, package installation, public hosting or external network is required. Paul owns private-use acceptance; qualified reviewers own scientific and archive-semantic acceptance.

## Invariants and falsifiers

- No representative is selected, no source identity is merged, and no original scientific receipt is overwritten. The interface labels the condition as a conditional view, never a corrected census.
- Numeric comparisons are resolved from a hash-verified local JSON artifact. Distinct original and conditional root pointers share the same metric-relative pointers. Case declarations cannot substitute literal numbers for sourced values.
- Missing/mismatched source bytes block comparison evaluation. JSON-pointer errors, booleans as numbers, nonfinite numbers, duplicate IDs, unknown conditions and a purported resolved identity fail before a bundle is written.
- Predicate outcomes are computed separately on original and conditional numbers. A lost-support mutation must change the status. Eight predicates from one treatment are not eight independent replications.
- Existing 0.2 case files, schemas, source fixtures and findings remain intact. New fields/rules require 0.3; old cases keep their original receipt version.
- A user can inspect alternative IDs and provenance, compare values and units in a table, and download the comparison without a server. Native disclosure controls remain keyboard-operable by construction; actual keyboard/focus/rendered behavior requires a live check.

The approach is falsified if a corrupted comparison source is shown as verified, conditional numbers appear as replacement counts, the source fields are not recoverable, or the original flash outcomes change. Structural checks do not establish uncoached comprehension or accessibility conformance.
