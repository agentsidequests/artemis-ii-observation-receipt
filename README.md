## The practical insight

One connected Sunset context corresponds to **4,290 archive products**, not 4,290 independent scientific events. In the original frozen reconstruction, a row-random split leaves **zero test products isolated at the complete-action layer**. A nonblank-target filter changes the sampled population; counting files or bytes changes its implicit weighting. The crew's flash reports also require an observation-opportunity and capability account before a camera null can carry evidential weight.

Those are different problems. The project separates four functions:

1. **Relationship:** preserve capture, representation, action, and context links before defining a split.
2. **Selection:** state the query and field-completion conditions instead of treating missing tags as negative labels.
3. **Weighting:** disclose whether a vote is an action, capture, product, byte, or scheduled opportunity.
4. **Detection:** distinguish temporal overlap from an instrument's demonstrated ability to detect the proposed signal.

This is metadata accounting and bounded methodological analysis, not a new lunar-science discovery or evidence that a deployed model was harmed. NASA and the field already have substantial relevant archive, survey, and open-science practice. See the essay and [prior-art crosswalk](STANDARDS-AND-PRIOR-ART-CROSSWALK.md).

JPL's 13 October reply reported that the science/archive teams confirmed identical images for `art002e009301` and `art002e015991`, originally `019A0860.NEF`. Only the latter is in the original counted cohort, so this confirmation does not reduce that cohort's denominator. The reply's likely catalogue explanation and intended future mitigation remain qualified. See the [refresh notes](PUBLIC-REFRESH-NOTES-2026-10-13.md) for the bounded factual summary and outstanding questions. No raw email or broader endorsement is included.

## Important qualifications before reuse

- **Original versus conditional:** the original filename-defined cohort is 22,818 products, 7,606 capture keys, and 2,166 reconstructed actions. Its physical identities are not independently validated. Reverse ordering changes the incumbent reconstruction. An order-robust candidate is inspectable but **not adopted**. Removing one ambiguous original action is a separate, explicitly conditional sensitivity, not a corrected census or all-ambiguity robustness proof.
- **Labels:** field-completion bounds are not a confidence interval or visual-content prevalence. The 24-plus-24 target-label pilot is a metadata-only proposal, not an image-label dataset. Its steward crosswalk must not be given to blinded reviewers.
- **Flashes:** NASA's accepted five-event annotation is retained. This project does not provide event photometry, calibrated human thresholds, precise locations, crater confirmation, capture-recapture inference, calibrated lunar impact flux, or a physical clustering result.
- **Clock semantics:** the annotation's 01:04 background-photo/context epoch is not certified ledger creation or an upper bound for every accepted event. The current app compares the later video with that metadata epoch only; coverage of every numbered event remains unestablished. See the [timing qualification](TIMING-SOURCE-QUALIFICATION.md). Historical receipts do not override it.
- **Withdrawal:** the old 26.96-fold / 3.58-magnitude physical observing-advantage interpretation is withdrawn. The rejected calculation remains auditable as history. Its distance-advantage chart and the old ledger-time flash timeline are **not distributed**. Read the [matched-epoch range reconciliation](paper-review/range-geometry/RANGE-RECONCILIATION.md) and timing qualification, not the old calculations, for the current dispositions.
- **Acceptance:** deterministic replay does not confer archive, physical-identity, label, scientific, standards, or specialist acceptance.

## Run the app from source

Requires Python 3.11 or newer; this candidate is qualified with Python 3.13.1. No third-party packages are needed for these commands. From the extracted repository:

```text
cd observation-receipt
python -B run.py demo
python -B run.py demo --case identity
python -B run.py demo --case identity-confirmed
python -B run.py demo --case robustness
python -B -m unittest discover -s tests -v
```

The four demo commands print their generated viewers. Open the corresponding `index.html`. A green source or replay check does not turn an unresolved proposition into a supported one. The flash demo remains the default. The original identity case is a historical control; identity-confirmed adds the scoped JPL statement without changing original counts. Robustness exposes hypothetical membership changes and separate completion costs.

For the case format, failure handling, and adding your own bounded case, read the [application README](observation-receipt/README.md) and [product contract](observation-receipt/docs/PRODUCT-CONTRACT.md). Editable installation is optional and needs a setuptools environment; it is not the tested zero-dependency entry path.

## Verify the package and analysis

From the repository root:

```text
python -B tools/verify_public_package.py
python -B -m src.prepare_presentation --check
python -B tools/replay_public.py --quick
python -B tools/replay_public.py --suite
```

The first command checks the entire shipped inventory. The presentation check replays its pinned inputs. The quick replay covers all four app cases, source-only range reconciliation, current presentation/essay/specialist qualifications and claim limits. The broader suite carries the retained scientific tests. Read [reproducibility and source availability](REPRODUCIBILITY.md) before interpreting its result. Private-history/delivery skips are explicit, not passes.

One historical full-text audit, Stage 11N, needs the exact NELIOTA extract that is not redistributed here. The full historical command deliberately stops at that missing dependency rather than marking it passed. Most analysis uses preserved NASA/PDS/JPL inputs and can run offline. Pixel regeneration and new source acquisition have separate dependencies and are not performed by these test commands.

## What is included and what is not

Included: the current essay and charts, specialist and methodological briefs, numerical source/result receipts, native evidence subsets, scientific code and tests, negative results, rejected hypotheses, identity uncertainty, and the Observation Receipt app.

Not included: the full mission archive, original private Git history, private operating instructions, contact or outreach drafts, messaging records, account details, credentials, or the withdrawn distance chart. Unverified journal full-text redistribution is replaced by a source locator and hash, not a fabricated replacement.

[Export provenance](EXPORT-PROVENANCE.json) distinguishes unchanged source bytes from owned public projections. Owned projection changes remove private paths, apply the approved public credit and license, repair reading-copy locators, and explicitly rebind dependent hashes and byte sizes. They do not recalculate scientific findings or alter native evidence payloads. [Method history](METHOD-HISTORY.md) provides the entry point to older results; those records are not automatically current recommendations.
