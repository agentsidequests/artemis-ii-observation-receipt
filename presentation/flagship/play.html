01

Machine learning / Relationships and testing

A new file.
But a new test?

Imagine practising on a photograph, then being tested on a different version of that same photograph. The filename is new. The underlying example is not.

Training is where a machine-learning system learns patterns from examples. Testing asks how well it handles examples kept out of that learning. Which examples to hold out depends on what you want it to handle next.

Here the goal is a new camera sequence. We are arranging files, not running an AI model. Watch which relatives end up on both sides. A different goal, such as converting the format of a known capture, would need a different test.

Invented miniature archive · 2 sequences · 2 capture keys each · 3 file formats per key

Relatives across the boundary

4 of 4 test files share a capture key with training.

Different formats of the same capture appear on both sides. A new filename alone does not test a new sequence.

Try keeping each capture together. Is that enough for the new-sequence question?

The math, the actual Artemis result, and the limit

Count each test file once: same capture as training, otherwise same reconstructed sequence, otherwise isolated at both declared layers.

In our separate, real constructed Artemis split canary, the original 4,511 test products decompose as 4,307 same-capture + 204 same-action-only + 0 action-isolated. That is a structural audit, not an observed NASA split, measured leakage, trained model or accuracy result. The original grouping remains filename/order conditioned.

Keeping sequences together prevents that declared relationship from crossing. It does not prove physical independence, prevent every shortcut, validate target labels, or provide a second independent Sunset. The appropriate boundary comes from the research question. An event-level test needs suitable separate events.

Why it matters beyond space: multiple scans from one patient, or several crops of one photograph, can raise the same question: are we testing a new file or the new situation we care about?

Statistics / Denominators and missing information

The blank is
part of the story.

You have a box of photographs. Some have names on the back. Others do not. Throwing out the unnamed ones makes counting easier, but it changes the question.

Those are the unchanged target fields in our original 7,606-key cohort, not verified descriptions of image content. We cannot read a blank as “not Sunset.” Instead, ask what different assumptions about the blanks would allow.

Hypothetical completed fields · not new labels or a prediction

For this completed-field example, every remaining blank is assigned a non-Sunset value. The original records are never edited.

Same denominator. An explicit assumption.

20.418% under this completion.

(1,553 + 0) / 7,606 × 100 = 20.418%

No blank is assigned Sunset in this hypothetical completion. That is an assumption, not a finding.

What the range means, and why 45.5% is a different answer

The completed recorded-field share is p(k) = (1,553 + k) / 7,606, with integer 0 ≤ k ≤ 4,193. Hold the already named fields fixed and assign every blank a value: the sharp possible range is 20.418% to 75.546%. Neither endpoint is more probable merely because we can calculate it.

Counting only the already named fields instead gives 1,553 / 3,413 = 45.502%. That excludes blanks; it does not resolve them. A confidence interval would require an appropriate sampling/model argument. These possibility bounds do not provide one, and recorded names may themselves be wrong.

Why it matters beyond space: an unanswered survey, a missing medical entry or an unlabeled training example is not automatically a negative. First declare which people or records the percentage describes.

Measurement / Coverage and detection

The world does not stop
when the recorder does.

Suppose twelve signals occur over a minute. A recorder can miss one because it was off, or because the signal did not pass its detection rule. Change the recorder. The invented world stays the same.

Entirely invented demonstration · not lunar events, real brightness or Artemis calibration

Twelve happened in the invented world

Only some leave a record.

Change a setting to see why the recorded count is not the total event count.

A non-detection is informative only relative to what the observation could have detected. The toy makes that distinction visible; it cannot tell us the Moon's impact rate.

For event i, the toy records it if 0 ≤ timeᵢ < on-time AND signalᵢ ≥ rule. We count the passing events. We do not estimate an unknown physical rate from them.

Real instruments need evidence for timing, coverage, response, noise and sensitivity. Human reports add attention and viewing conditions. Our bounded Artemis camera test is entirely separate: 9 of 162 synthetic trials recovered at the largest tested digital level in one transcoded clip, not a calibrated physical threshold. No toy setting corresponds to that result.

Why it matters beyond space: a wildlife camera that was off, a sensor with unknown sensitivity and a missed faint star all require a question about observation before a question about absence.
